# Handoff: KinDee — Auth + Onboarding + Core logging (P0)

## Overview

KinDee เป็นเว็บแอป (PWA) นับแคลอรีสำหรับผู้ใช้ไทย ครอบคลุมทั้งอาหารปรุงสำเร็จและสินค้าบรรจุภัณฑ์จากร้านสะดวกซื้อ/ห้าง จุดแข็งคือความเข้าใจอาหารไทยและการสแกนบาร์โค้ดเป็นทางเพิ่มอาหารหลัก

ชุดนี้ครอบคลุม:

- **กลุ่ม A — เข้าสู่ระบบ** (หน้า 1 Splash, 2 Login/Signup, 3 ยืนยันอีเมล, 4 ลืมรหัสผ่าน) + หน้าอ่าน **เงื่อนไขการใช้งาน / นโยบายความเป็นส่วนตัว (PDPA)**
- **กลุ่ม B — ตั้งค่าครั้งแรก** (หน้า 6 ข้อมูลพื้นฐาน, 7 ร่างกาย, 8 กิจกรรม, 9 เป้าหมาย, 10 สรุปเป้า)
- **กลุ่ม C — P0 ใช้งานหลัก** (หน้า 11 วันนี้, 12 ล่าสุด, 13 ค้นหา, 14 สแกนบาร์โค้ด, 16 ถ่ายรูป (เบา), 18 เลือกปริมาณ, 15 ไม่พบบาร์โค้ด (bottom sheet), 20 แก้ไขรายการ)

ยังไม่รวมในรอบนี้: 5 Welcome, 17 ผล AI, 19 รายละเอียดอาหาร, 21–22 ประวัติ, 23–27 โปรไฟล์/ตั้งค่า

## About the Design Files

ไฟล์ในบันเดิลนี้เป็น **design reference ที่เขียนด้วย HTML** — เป็นโปรโตไทป์ที่แสดงหน้าตาและพฤติกรรมที่ต้องการ **ไม่ใช่ production code ให้ก๊อปไปใช้ตรง ๆ**

งานคือ **สร้างดีไซน์เหล่านี้ขึ้นใหม่ในโค้ดเบสจริง** ด้วย pattern และไลบรารีที่โปรเจกต์นั้นใช้อยู่ (React + Tailwind, Vue, SvelteKit ฯลฯ) ถ้ายังไม่มีโค้ดเบส แนะนำ **React + TypeScript + Vite + PWA (vite-plugin-pwa)** เพราะดีไซน์ทั้งชุดเป็น PWA mobile-first อยู่แล้ว

`KinDee P0.dc.html` ใช้ runtime ภายในของเครื่องมือออกแบบ (`<x-dc>`, `support.js`, `<sc-for>`, `<sc-if>`) — **อย่าพยายาม port runtime นี้** ให้อ่านเป็น spec: markup + inline style คือหน้าตาที่ต้องการ, คลาส `Component extends DCLogic` คือ state machine ที่ต้องการ (แปลงเป็น React component/hook หรือ store ตามโค้ดเบส)

## Fidelity

**High-fidelity (hifi)** — สี ตัวอักษร ระยะห่าง มุมโค้ง สถานะ และ copy ภาษาไทยทั้งหมดเป็นค่าจริงที่ใช้ได้เลย ให้ทำตาม pixel-perfect โดยแมปเข้ากับ design system ของโค้ดเบส (ถ้ามี)

ข้อยกเว้นที่เป็น placeholder โดยตั้งใจ:
- โลโก้ KinDee = สี่เหลี่ยมมุมโค้ง + ไอคอน Phosphor `bowl-food`
- มาสคอต (ใช้เฉพาะ empty state) = inline SVG ชามหน้ายิ้มแบบเรียบ
- มุมมองกล้อง = พื้นไล่เฉดเทาเข้ม (ของจริงคือ `<video>` จาก `getUserMedia`)
- รูปสินค้า/รูปฉลาก = ไอคอนในกรอบสี่เหลี่ยมมุมโค้ง

## Screens / Views

> ทุกหน้าอยู่ในโครง `390 × 844` เดียวกัน มี layer ซ้อนกันด้วย z-index (ต่ำ → สูง): tab bar `3` · toast `4` · แผงเพิ่มอาหาร `6` · onboarding `7` · bottom sheet เลือกปริมาณ `8` · auth `9` · status bar ของ OS `10`
> **สำคัญ:** overlay ทุกชั้นต้องอยู่ใต้ status bar และเว้น safe area 47px ไว้เสมอ

### 1. Splash (หน้า 1)

- **Purpose:** จุดเข้าครั้งแรก ถ้ามี session อยู่แล้วให้ข้ามไปหน้าวันนี้เลย (ออกแบบ loading สั้น ๆ ไว้)
- **Layout:** จัดกลางแนวตั้ง padding `51px 26px 34px`, text-align center, gap 16px
- **Components:** โลโก้ 76×76 radius 24 พื้น `accent` ไอคอน `bowl-food` 36px → ชื่อ “KinDee” 30px/500 → tagline 14.5px `text-muted` กว้างสุด 264px → ปุ่มหลัก “เริ่มใช้งาน” (52px, `accent`) → ปุ่มรอง “เข้าสู่ระบบ” (52px, outline `accent-line`) → บรรทัดล่าง ไอคอน `arrows-clockwise` + “ข้อมูลซิงก์ให้อัตโนมัติ เปลี่ยนเครื่องก็ใช้ต่อได้” 12px

### 2. เข้าสู่ระบบ / สมัครสมาชิก (หน้า 2)

- **Purpose:** หน้าเดียวสลับสองโหมด (`signup` / `login`) ไม่แยกหน้า
- **Layout:** scroll เดียว padding `51px 20px 26px`; ปุ่มย้อนกลับ 44×44 → หัวข้อ 24px → คำอธิบาย 13.5px → ปุ่ม Google → ตัวคั่น “หรือ” → ฟอร์ม → consent 11.5px
- **ปุ่ม Google (เด่นที่สุด):** 52px, พื้น `surface`, ขอบ `border-strong`, hover ขอบ `accent-line`, โลโก้ 19px + “ดำเนินการต่อด้วย Google”
- **ตัวคั่น:** เส้น gradient จางไปโปร่งใสสองข้าง + คำ “หรือ” 12px (ตาม Nocturne: เส้นจางที่ปลาย)
- **ฟอร์ม:** label 12px + input 52px radius 12 พื้น `surface`; ช่องรหัสผ่านมีปุ่มตา 44×44 สลับ `password/text`; ปุ่ม submit 52px `accent` (ตอนโหลดมีไอคอน `circle-notch` หมุน 1s linear + ข้อความ “กำลังดำเนินการ…”)
- **สถานะ:** ปกติ / กำลังโหลด / อีเมลผิดรูปแบบ / รหัสผ่านสั้นเกินไป (โหมดสมัคร) / รหัสผ่านไม่ถูก / บัญชีนี้มีอยู่แล้ว / ออฟไลน์
  - error: ขอบฟิลด์เปลี่ยนเป็น `status-over` + บรรทัดข้อความ 12.5px สี `warn-text` + ไอคอน `warning-circle` — **ไม่ใช้แดง ไม่ใช้คำตำหนิ**
  - ออฟไลน์: กล่อง `accent-tint` อธิบายว่าบันทึกในเครื่องได้ปกติ เดี๋ยวซิงก์ให้ + ปุ่ม submit จางลง (`#b2a9d6`) และกดไม่ทำงาน
- **ลิงก์:** “ลืมรหัสผ่าน” (แสดงเฉพาะโหมด login) · สลับโหมด · consent มีลิงก์ไปหน้าเงื่อนไข/ความเป็นส่วนตัว
- **Copy consent (ใช้ตรงนี้ได้เลย):** “การใช้งานต่อถือว่ายอมรับ *เงื่อนไขการใช้งาน* และ *นโยบายความเป็นส่วนตัว* · ข้อมูลน้ำหนักและมื้ออาหารเก็บในบัญชีของคุณ ซิงก์ให้เฉพาะอุปกรณ์ที่คุณล็อกอิน”

### 3. ยืนยันอีเมล (หน้า 3)

- ไอคอน `envelope-simple-open` ในกล่อง 60×60 `accent-tint` → หัวข้อ “ส่งลิงก์ไปแล้วนะ” → อีเมลที่ส่งไป (ตัวหนา 500) + อธิบายว่ายืนยันแล้วจะซิงก์ทุกเครื่อง
- ปุ่มหลัก “ยืนยันแล้ว ไปตั้งค่าต่อ” → เข้า onboarding ขั้น 1
- ปุ่ม “ส่งอีกครั้ง” **ปิดใช้งาน 60 วินาที** แสดง “ส่งอีกครั้งได้ในอีก N วิ” (ขอบ `border-strong`, ข้อความ `text-muted`, cursor default) แล้วกลับมาใช้ได้ (ขอบ `accent-line`)
- ลิงก์ “ใช้อีเมลอื่น” → กลับหน้าสมัคร

### 4. ลืมรหัสผ่าน (หน้า 4)

- ฟอร์ม: หัวข้อ “ลืมรหัสผ่าน ไม่เป็นไร” + ช่องอีเมล + ปุ่ม “ส่งลิงก์ตั้งรหัสใหม่”
- สถานะส่งสำเร็จ: ไอคอน `paper-plane-tilt` + “ส่งลิงก์ตั้งรหัสใหม่แล้ว” + ข้อความแบบไม่ยืนยันว่าอีเมลนี้มีบัญชีจริง (ปลอดภัยกว่า) + ปุ่มกลับไปเข้าสู่ระบบ

### เงื่อนไขการใช้งาน / นโยบายความเป็นส่วนตัว

- **Purpose:** หน้าอ่านในแอป เข้าจากลิงก์ consent (และควรเข้าได้จาก ตั้งค่า › เกี่ยวกับ ด้วย)

### 6–10. ตั้งค่าครั้งแรก (onboarding)

โครงร่วมทุกขั้น: แถบความคืบหน้า 5 ช่อง สูง 4px (ช่องที่ผ่านแล้ว = `accent`, ที่เหลือ = `border`) → ปุ่มย้อนกลับ + “ขั้นที่ N จาก 5” → หัวข้อ 24px + คำอธิบาย 13.5px → เนื้อหา scroll → footer ติดล่าง (`surface`, เส้นบน 1px, padding `12px 16px 34px`) มีปุ่มหลัก 52px + footnote 11.5px กลาง
**ห้ามมีปุ่มข้าม** — footnote อธิบายเหตุผล: “ทุกค่าจำเป็นต่อการคำนวณ เลยยังข้ามไม่ได้ ขอโทษด้วยนะ”

- **8 ระดับกิจกรรม** — 4 การ์ด (ไอคอน + ชื่อ + คำอธิบายเป็นรูปธรรม + วงกลมติ๊ก `check-circle` fill): นั่งทำงานเป็นหลัก 1.2 / เบา 1.375 / ปานกลาง 1.55 / หนัก 1.725
- **9 เป้าหมาย** — 3 การ์ด **น้ำหนักภาพเท่ากันทุกอัน** (ห้ามเน้นการลดน้ำหนัก): ลดน้ำหนัก −500 / คงน้ำหนัก 0 / เพิ่มน้ำหนัก +350 kcal
- **10 สรุปเป้าหมาย** — การ์ดตัวเลขใหญ่ 44px + “kcal · คำนวณอัตโนมัติ|ตั้งเอง” → ตาราง “ตัวเลขนี้มาจากไหน” 3 แถว (BMR / คูณระดับกิจกรรม / ปรับตามเป้าหมาย) แต่ละแถวมีหมายเหตุตัวเลขที่ใช้ → กล่องห่วงใยกรณีต่ำกว่าเกณฑ์ปลอดภัย → ลิงก์ “ปรับเอง” เปิดช่องกรอกเป้าเอง → ปุ่ม “เริ่มใช้งาน” (หรือ “บันทึกเป้าหมาย” เมื่อเข้ามาแก้)

**สูตรคำนวณ (Mifflin–St Jeor):**
```
BMR = 10×น้ำหนัก(กก.) + 6.25×ส่วนสูง(ซม.) − 5×อายุ + (ชาย: +5 | หญิง: −161)
TDEE = BMR × activityFactor
rawTarget = TDEE + goalDelta          // lose −500, keep 0, gain +350
floor = ชาย 1500 | หญิง 1200
target = max(floor, round(rawTarget / 10) × 10)
```
ถ้า `rawTarget < floor` → ดันขึ้น floor อัตโนมัติ + แสดงข้อความ **น้ำเสียงห่วงใย ไม่ใช่เตือน** และแนะนำให้ปรึกษาแพทย์/นักกำหนดอาหาร (copy อยู่ในไฟล์: `obFloorText`)

- **หน้า 20 แก้ไขรายการ** = sheet เดียวกัน + ปุ่มลบ 52×52 ขอบ `danger` ด้านซ้ายของปุ่มบันทึก (กรณีเดียวที่ใช้แดง) และปุ่มหลักเปลี่ยนเป็น “บันทึกการแก้ไข”

## Interactions & Behavior

**Auth**
- Splash → “เริ่มใช้งาน” = login screen โหมด signup · “เข้าสู่ระบบ” = โหมด login
- submit: validate อีเมล (ต้องมี `@` และ `.`) → รหัสผ่าน ≥ 8 ตัว → loading ~950ms → signup ไปหน้ายืนยันอีเมล / login เข้าแอป + toast “ยินดีต้อนรับกลับ ข้อมูลซิงก์เรียบร้อยแล้ว”
- Google: loading ~900ms → โหมด signup เข้า onboarding ทันที (ไม่ต้องยืนยันอีเมล) / โหมด login เข้าแอป
- แก้ไขฟิลด์ = ล้าง error ของฟิลด์นั้น
- ยืนยันอีเมล: countdown 60→0 วินาที (setInterval 1s, clear เมื่อออกจากหน้า/unmount), ส่งอีกครั้งแล้วเริ่มนับใหม่ + toast
- consent link → หน้าเงื่อนไข (จำหน้าที่มาไว้ใน `termsBack` เพื่อกดย้อนกลับได้ถูก)

**Onboarding**
- ถัดไป: ขั้น 1–4 เดินหน้า, ขั้น 5 = ยืนยันเป้า → เก็บ target → ผู้ใช้ใหม่เข้าหน้าวันนี้แบบ empty + toast “เริ่มได้เลย เป้าวันละ N kcal”; โหมดแก้เป้า → กลับหน้าเดิม + toast “อัปเดตเป้าเป็น N kcal แล้ว”
- ย้อนกลับ: ขั้น >1 ถอยหนึ่งขั้น, ขั้น 1 ปิด flow
- ค่าที่เลือกทุกอันคำนวณเป้าใหม่แบบสด (หน้า 10 อัปเดตทันที)
- “ปรับเอง”: เปิดช่องกรอก ค่าเริ่มต้นเป็นค่าที่คำนวณได้; ถ้ากรอกตัวเลข > 0 จะใช้ค่านั้นและ source เปลี่ยนเป็น “ตั้งเอง”
- แท็บ “ฉัน” = เข้าหน้าสรุปเป้าในโหมดแก้ไข (ของจริงคือหน้า 23 → 25)
- ⚠️ ตามบรีฟ: เมื่อผู้ใช้แก้ค่าที่กระทบการคำนวณในหน้าโปรไฟล์ **ต้องถามก่อนว่าจะคำนวณเป้าใหม่ไหม** ห้ามเปลี่ยนเป้าเงียบ ๆ (ยังไม่ได้ออกแบบ dialog นี้)

**Core logging**
- FAB / ปุ่มลัดสแกน / ปุ่ม `+` ของแต่ละกลุ่มมื้อ → เปิดแผงเพิ่มอาหาร (ปุ่มของกลุ่มมื้อจะเซ็ตชิปมื้อให้ตรง)
- แตะการ์ด “กินบ่อย” หรือปุ่ม `+` ในแถวล่าสุด = บันทึกทันที (≤ 4 tap ตั้งแต่เปิดแอป) → ปิดแผง → toast พร้อม แก้ไข/เลิกทำ
- “เลิกทำ” = ลบ entry ที่เพิ่งเพิ่ม · “แก้ไข” = เปิด sheet โหมดแก้ไขของ entry นั้น
- สแกนเจอ → sheet เลือกปริมาณซ้อนบนกล้อง → บันทึก → กลับสู่โหมดเล็ง + ตัวนับ +1 (สแกนต่อเนื่อง)
- ค้นหา: debounce ~420ms (สถานะ “กำลังค้นหา” ระหว่างนั้น) แล้วกรองด้วย substring ของชื่อ/แบรนด์ + ชิปหมวด
- ปัดแถวอาหาร: pointerdown/move/up, clamp −90…0, snap −84 หรือ 0
- ลูกศรวันที่: ย้อนหลัง = โหมดอ่านอย่างเดียว

**Animations** (ทั้งหมดต้องเคารพ `prefers-reduced-motion: reduce`)
`kd-sheet` slide-up .24–.26s `cubic-bezier(.22,.61,.36,1)` · `kd-up` toast/sheet fade+rise .2–.22s · `kd-pulse` skeleton 1.2–1.6s ease-in-out infinite · `kd-scan` เส้นสแกน 1.5s alternate · `kd-spin` 1s linear · วงแหวน transition `stroke-dasharray .45s`

## State Management

state ที่ต้องมี (ดูคลาส `Component` ในไฟล์ HTML ประกอบ):

```
auth:      auth (null|'splash'|'login'|'verify'|'forgot'|'terms'), authMode('signup'|'login'),
           authErr (null|'email'|'pass'|'weak'|'exists'|'offline'), authLoading,
           email, pass, showPass, resendLeft, forgotSent, termsTab, termsBack
profile:   sex, bDay/bMonth/bYear, height, weight, activity, goal, targetSet, manualOpen, manual
onboard:   ob (เปิด/ปิด), obStep 1..5, obEdit
log:       entries[{uid, meal, foodId, unitIx, amount}], day (0=วันนี้), scene (สถานะรีวิว)
add flow:  addOpen, addTab('recent'|'search'|'scan'|'photo'), meal, query, searching, filter
scan:      scan('aiming'|'fetching'|'notfound'|'offline'|'denied'), scanCount, torch
qty sheet: qty{foodId, editing}, unitIx, amount, gramOpen, gram
ui:        toast{text, undoUid}, swipeId, swipeDx, dragging
```

**Data fetching ที่ต้องต่อของจริง:** auth + email verification (แนะนำ Firebase Auth / Supabase Auth ทำ Google + email ได้ครบ) · sync โปรไฟล์และ log ต่อบัญชี (ต้องรองรับ offline-first: เขียนลง IndexedDB ก่อน แล้ว sync ทีหลัง — แถบ “ยังไม่ได้ซิงก์” ผูกกับสถานะคิวนี้) · ค้นหาอาหาร/สินค้า (ต้องรองรับคลังในเครื่อง ~320 รายการตอนออฟไลน์) · ค้นบาร์โค้ด (มีคิวรอค้นตอนออฟไลน์) · OCR ฉลากโภชนาการ · AI ทายจากรูป (มีโควตาต่อวัน)

**PWA:** service worker + offline shell, manifest, ไม่มี native nav bar (header ทำเอง), ขอสิทธิ์กล้องตอนจะใช้จริงเท่านั้น

## Accessibility (ข้อกำหนด ห้ามพลาด)

- คอนทราสต์ผ่าน WCAG 2.1 AA ทุกคู่สี — ข้อความรองเล็กสุดที่ใช้ได้คือ `#595d6c` บนพื้น `#f3f5fe`/`#fbfbfe` (≈6.3:1); `#9397ab` ใช้ได้กับเส้น/พื้นตกแต่งเท่านั้น
- touch target ≥ 44×44px ทุกจุด · ทุกไอคอนที่กดได้มี `aria-label` ภาษาไทย
- ห้ามสื่อความหมายด้วยสีอย่างเดียว (ป้ายคุณภาพข้อมูล = ไอคอน + ข้อความ; error = ไอคอน + ข้อความ)
- รองรับขยายตัวอักษรถึง 200% โดย layout ไม่พัง (ไทยยาวกว่าอังกฤษ ~20% และชื่อสินค้ายาวมาก) → ห้าม fix height ให้ข้อความ ใช้ min-height
- `:focus-visible { outline: 2px solid #796cbf; outline-offset: 2px }` ทุก element ที่โฟกัสได้ — ห้ามปล่อยเป็นวงน้ำเงินดีฟอลต์
- หน้าสแกนต้องมีทางเลือกไม่ใช้กล้อง (กรอกเลขเอง) เสมอ
- เคารพ `prefers-reduced-motion`

## Copy / Tone

น้ำเสียง **เป็นกันเองมาก คุยเหมือนเพื่อน** และ **เป็นกลาง ไม่ตัดสิน**
- ห้ามใช้คำ “เกิน” ในเชิงตำหนิ, “พลาด”, “ล้มเหลว”, “ผิดพลาด” — กินเกินเป้าใช้ “เกินมา 120” เฉย ๆ + บริบทที่ปลอบ (“ค่าเฉลี่ยสัปดาห์นี้ยังอยู่ในช่วงเป้าหมาย”)
- ฉลองความสม่ำเสมอ ไม่ฉลองการกินน้อย
- ข้อความไทยทั้งหมดในไฟล์ใช้ได้เลย (copy จริง ไม่ใช่ lorem)
